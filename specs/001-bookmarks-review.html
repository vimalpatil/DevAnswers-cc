Bookmarks: save questions for later

Authenticated users can bookmark questions from the list or detail view, and see them in a private Saved Questions section on their profile. Bookmarks are stored server-side, so they persist across sessions and devices.

1Summary

The problem: DevAnswers has no way to keep track of a question. Users who find something useful have to search for it again. Bookmarks give them a reason to come back and a reason to keep an account.

2User stories

Who benefits and how.

  • US-1As an authenticated user, I can bookmark a question from the question list or the detail page, so I can find it later.
  • US-2As an authenticated user, I can remove a bookmark from the same places, or from my profile.
  • US-3As an authenticated user, I can see all my saved questions in a "Saved Questions" section on my profile and open any of them in one click.
  • US-4As an authenticated user, my bookmarks are still there after I log out and back in, or on another device.
  • US-5As a logged-out visitor, I can see that bookmarking exists and I'm told to log in when I try it.

3Acceptance criteria

Every criterion is testable and maps to at least one test in the test plan.

IDCriterion
AC-1An authenticated user can bookmark a question from QuestionCard and from the detail view (QuestionContent). After the server confirms, it appears in GET /api/bookmarks.
AC-2An authenticated user can remove a bookmark from QuestionCard, QuestionContent, or Saved Questions. Afterwards it is no longer returned.
AC-3A bookmark control renders on every QuestionCard and in the QuestionContent header.
AC-4The control's state updates immediately, before the API responds (optimistic). If the request fails, the state reverts and an error is shown.
AC-5While a request is in flight for a question, its control is disabled, so double-clicks can't conflict.
AC-6Bookmarks are stored server-side and survive logout/login and fresh browsers. They are not stored in localStorage.
AC-7Users can only read and modify their own bookmarks. No endpoint accepts a user ID; the user always comes from the JWT.
AC-8/profile shows "Saved Questions" using QuestionList and QuestionCard, most recently saved first by default.
AC-9With zero bookmarks, an empty state shows "No saved questions yet" with a hint, not the home page's "be the first to ask" text.
AC-10All /api/bookmarks endpoints return 401 without a valid token. A logged-out click shows a login prompt, and no request is sent.
AC-11On app load with a stored session, or right after login, bookmarked IDs are fetched once. Controls on every page reflect the state without fetching again.
AC-12On logout, all bookmark state in Redux is cleared.
AC-13Deleting a question deletes its bookmarks, and it disappears from everyone's Saved Questions.
AC-14Existing tests that build a Redux store without a bookmark slice keep passing: selectors handle a missing slice.

5API contract

New router src/routes/bookmarks.js mounted at /api/bookmarks. Every route uses authenticate. Responses use the standard { success, message, data } envelope.

GET/api/bookmarks

The current user's bookmarked questions, most recently saved first. Same shape as GET /api/questions items, plus answerCount and bookmarkedAt. Bookmarks whose question has been deleted are left out.

200 · data: [] when empty401
GET/api/bookmarks/ids

Lightweight list of bookmarked question IDs, used at startup to drive every control's state.

200 · ["665f…", …]401
PUT/api/bookmarks/:questionId

Bookmark a question. Idempotent: an upsert, and 200 whether it was created or already existed. No body.

200 · { questionId, bookmarked: true, bookmarkedAt }400 invalid ID404 question not found401
DELETE/api/bookmarks/:questionId

Remove a bookmark. Idempotent, and doesn't require the question to exist, so stale bookmarks can always be removed.

200 · { questionId, bookmarked: false }400 invalid ID401

Example: GET /api/bookmarks

{
  "success": true,
  "message": "Bookmarks fetched successfully",
  "data": [{
    "_id": "665f…", "title": "How do I …", "description": "…",
    "tags": [{ "_id": "…", "name": "react" }],
    "author": { "_id": "…", "name": "Alice" },
    "voteCount": 3, "views": 12, "answerCount": 2,
    "createdAt": "2026-01-15T12:00:00.000Z",
    "bookmarkedAt": "2026-11-20T09:30:00.000Z"
  }]
}

Validation & authorization rules

  • Path validation: questionId is checked with mongoose.Types.ObjectId.isValid before any query, giving 400 "Invalid question ID".
  • Identity: the owner is always req.user.id. No endpoint reads a user ID from params, query, or body. This is what keeps bookmarks private.
  • No admin exception: admins cannot read or change other users' bookmarks.
  • Own questions: users may bookmark their own questions.
  • Concurrency: PUT is an upsert. A duplicate-key error (E11000) from a concurrent create is treated as success, not a 500.
  • Rate limiting: the existing global limiter applies (100 requests per 15 minutes per IP). No bookmark-specific limit.
  • Existing endpoints: only DELETE /api/questions/:id changes, to cascade to bookmarks. Public question endpoints do not gain an isBookmarked field.

6Data model

One new collection. User, Question, Answer and Tag are unchanged.

// devanswers-backend/src/models/Bookmark.js
const bookmarkSchema = new mongoose.Schema({
  user:     { type: ObjectId, ref: "User",     required: true },
  question: { type: ObjectId, ref: "Question", required: true },
}, { timestamps: true });

bookmarkSchema.index({ user: 1, question: 1 }, { unique: true });
bookmarkSchema.index({ user: 1, createdAt: -1 });
bookmarkSchema.index({ question: 1 });

src/app.js imports the model alongside the others. Seed data (populate-db.js) may optionally add bookmarks and must then clear them too.

8Edge cases & error handling

Expected behaviour in failure and race scenarios.

CaseExpected behaviour
Expired JWT at startupThe ids fetch gets 401, controls show "not bookmarked", and the user is not force-logged-out (matches today's behaviour). A later click fails, reverts, and alerts.
Double-clickThe second click is ignored while pending. The button is disabled.
Network error on add or removeOptimistic state reverts. An alert shows the server message or "Failed to update bookmark".
Bookmark a question deleted meanwhilePUT returns 404. The UI reverts with "Question not found".
Remove a bookmark whose question was deletedDELETE returns 200 (idempotent).
Question deleted while bookmarkedThe bookmarks are cascade-deleted. The list also skips any orphaned bookmark as a defence.
Concurrent PUT from two tabsUnique index plus upsert: one document is created, and both requests get 200.
Invalid ObjectId in the path400 "Invalid question ID".
Two users on the same browserLogout clears the slice, and login fetches the new user's IDs.
Tabs out of syncThe other tab shows stale state until reload, and its actions still succeed (idempotent).
Many bookmarksAll are returned with no server pagination, consistent with GET /api/questions. QuestionList paginates at 5 per page.

Manual check

  1. Log in, then bookmark from the home page and from a detail page. Each icon fills instantly.
  2. Reload. The icons are still filled.
  3. Open /profile. Both questions are listed, newest saved first.
  4. Unbookmark one there. It disappears.
  5. Log out and log in as another user. Nothing is bookmarked.
  6. Delete a bookmarked question as its author. It disappears from Saved Questions.
